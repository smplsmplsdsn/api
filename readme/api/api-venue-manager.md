

# 会場管理者登録・解除API

## エンドポイント

`POST /venue_manager?service=standup`

会場の担当管理者への登録、または自分自身の担当管理者登録を解除する。

## 認証・権限

ログインが必要。

- `users.status` が `active` であること。
- 管理者の追加（`add`）には、`standup` サービスの `member` ロールと `venue_manager` ロールが両方 `active` であること。
- 管理者の解除（`remove`）には、会場管理者ロールは必要ない。ただし、ユーザーが有効であること。

※ `hasActiveRole()` によるロール確認では、`member` ロールも有効であることを確認する。

## リクエスト

JSON形式で送信する。

### パラメータ

| パラメータ | 必須 | 説明 |
|---|---|---|
| `action` | 必須 | 操作内容。`add` または `remove` |
| `venue_id` | 必須 | 対象の会場ID |

`venue_id` は1以上の整数型で送信する。文字列型は受け付けない。

### リクエスト例

管理者の追加：

```json
{
  "action": "add",
  "venue_id": 113
}
```

管理者の解除：

```json
{
  "action": "remove",
  "venue_id": 113
}
```

## 処理内容

### 管理者の追加（`add`）

1. 有効な会場管理者ロールを確認する。
2. 対象会場が存在し、`status` が `active` であることを確認する。
3. 自分自身の管理者登録を確認する。
4. 登録状態に応じて処理する。

| 現在の登録状態 | 処理 |
|---|---|
| 登録なし | 新規登録する |
| `active` | 何もしない |
| `inactive` | `active` に変更する |

### 管理者の解除（`remove`）

1. 対象会場が存在し、`status` が `active` であることを確認する。
2. 自分自身の管理者登録を確認する。
3. 自分自身の登録が `active` の場合、`inactive` に変更する。

- 他のユーザーの管理者登録は解除できない。
- 自分自身の登録が存在しない場合は何もしない。
- すでに `inactive` の場合も何もしない。

## レスポンス

### 成功時

```json
{
  "success": true
}
```

追加・解除のどちらも同じレスポンスを返す。

## エラー時

| HTTPステータス | エラー | 説明 |
|---|---|---|
| 400 | `Invalid request body` | JSON形式のリクエストではない |
| 400 | `Invalid action` | `action` が `add` または `remove` ではない |
| 400 | `Invalid venue id` | 会場IDが1以上の整数型ではない |
| 401 | `Unauthorized` | 未ログイン、またはユーザーが無効 |
| 403 | `Forbidden` | 管理者追加の権限がない |
| 404 | `Venue not found` | 会場が存在しない、または有効ではない |
| 405 | `Method not allowed` | POST以外のリクエスト |
| 500 | `Internal server error` | サーバー内部エラー |

## 補足

- 追加・解除処理はトランザクション内で実行する。
- 対象会場のレコードをロックしてから処理する。
- 管理者の追加は、自分自身の登録のみを対象とする。
- 解除も自分自身の登録のみを対象とする。
- 管理者登録の解除は物理削除ではなく、`status` を `inactive` に変更する。
