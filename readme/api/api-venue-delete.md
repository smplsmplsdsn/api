

# 会場削除API

## エンドポイント

`POST /venue_delete?service=standup`

指定した会場を削除、または非表示にする。

## 認証・権限

ログインが必要。以下の条件を満たすユーザーが利用できる。

- `users.status` が `active`
- 次のいずれかを満たすこと
  - `standup` サービスの `member` ロールと `comedian` ロールが `active` で、コメディアン情報も `active`
  - `standup` サービスの `member` ロールと `venue_manager` ロールが `active`

### 会場の削除権限

- 有効な担当管理者がいる場合は、その会場の担当管理者のみ削除できる。
- 有効な担当管理者がいない場合は、上記の利用権限を持つコメディアンまたは会場管理者が削除できる。

※ **この削除APIにおける担当管理者の有無の判定**は、`standup_venue_managers.status = active` のレコードが存在するかどうかで行う。紐付く `users.status` や `member`・`venue_manager` ロールの状態は、この判定SQLでは確認しない。担当管理者がいる場合、削除実行者については有効な `venue_manager` ロールと、本人の `standup_venue_managers.status = active` の登録を確認する（本人の有効な `member` ロールは `hasActiveRole()` の判定に含まれる）。

この判定は `/venue` の有効な担当管理者判定と異なる。例えば担当登録だけが `active` で担当者のロールが無効な場合も、このAPIでは「担当管理者あり」として扱う。これは現行実装の記録であり、API間で判定を統一するかどうかは実装改善の検討事項とする。

## リクエスト

### パラメータ

JSON形式で送信する。

| パラメータ | 必須 | 説明 |
|---|---|---|
| `id` | 必須 | 削除対象の会場ID |

`id` は1以上の整数として送信する。文字列ではなく、JSONの整数型である必要がある。

### リクエスト例

```json
{
  "id": 113
}
```

## 削除条件

### 1. 未来または日時未定のイベントで使用されている場合

以下のいずれかに該当するイベント候補がある場合は削除できない。

- `start_at` または `open_at` のうち、`start_at` を優先した日時が現在日時以降である。
- `start_at` と `open_at` の両方が未設定である。

この場合はエラーを返す。

### 2. 過去のイベントで使用された履歴がある場合

イベント候補で使用された履歴がある場合は、物理削除せず、会場の `status` を `inactive` に変更する。

### 3. イベントで使用された履歴がない場合

イベント候補で使用された履歴がない場合は、会場レコードを物理削除する。

## レスポンス

### 成功時

非表示にした場合：

```json
{
  "success": true,
  "id": 113,
  "action": "deactivated"
}
```

物理削除した場合：

```json
{
  "success": true,
  "id": 113,
  "action": "deleted"
}
```

| 項目 | 説明 |
|---|---|
| `success` | 成功時は `true` |
| `id` | 処理対象の会場ID |
| `action` | 実行した処理。`deactivated` または `deleted` |

### エラー時

| HTTPステータス | エラー | 説明 |
|---|---|---|
| 400 | `Invalid venue id` | 会場IDが不正 |
| 400 | `イベントで使われているため削除できません` | 未来または日時未定のイベントで使用中 |
| 401 | `Unauthorized` | 未ログイン、またはユーザーが無効 |
| 403 | `Forbidden` | 削除権限がない |
| 404 | `Venue not found` | 会場が存在しない、または有効ではない |
| 405 | `Method not allowed` | POST以外のリクエスト |
| 500 | `通信エラーが発生しました` | サーバー内部エラー |

## 補足

- 対象会場の `status` が `active` でない場合は削除対象にならない。
- 削除・非表示処理はトランザクション内で実行する。
- `deactivated` の場合、会場レコードとイベント候補の関連は維持される。
- `deleted` の場合、イベント候補での使用履歴がないことを確認してから物理削除する。
