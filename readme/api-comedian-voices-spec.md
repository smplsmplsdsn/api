# Standup API：コメディアン投稿（つぶやき）仕様

## 1. 概要

コメディアンが短いテキストを投稿し、コメディアンごとの投稿一覧として取得できる機能。

投稿の取得には投稿IDを使ったカーソル方式を採用し、初回取得・新着取得・過去投稿の追加取得を区別する。

## 2. データベース

### テーブル：`standup_comedian_voices`

| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | `BIGINT UNSIGNED` | 投稿ID。自動採番の主キー |
| `comedian_id` | `BIGINT UNSIGNED` | 投稿者のコメディアンID |
| `text` | `TEXT` | 投稿本文 |
| `created_at` | `TIMESTAMP` | 投稿日時。登録時に自動設定 |

### 制約・インデックス

- `id` は主キーかつ自動採番。
- `comedian_id` は `standup_comedians.id` を参照する外部キー。
- コメディアンが削除された場合、関連する投稿も `ON DELETE CASCADE` により削除される。
- コメディアンIDと投稿日時、および投稿日時に関するインデックスを設定する。

## 3. API 共通仕様

- エンドポイント：`services/standup/voices.php`
- 対応メソッド：`GET`、`POST`
- 対応外のメソッドでは `405 Method Not Allowed` を返し、`Allow: GET, POST` ヘッダーを設定する。
- レスポンス形式は JSON。
- `Content-Type: application/json; charset=UTF-8` を設定する。
- エラー時は原則として `{"success": false, "error": "..."}` を返す。

## 4. GET：投稿一覧の取得

### リクエストパラメーター

| パラメーター | 必須 | 説明 |
| --- | --- | --- |
| `comedian_id` | 必須 | 取得対象のコメディアンID |
| `after_id` | 任意 | 指定した投稿IDより新しい投稿を取得するカーソル |
| `before_id` | 任意 | 指定した投稿IDより古い投稿を取得するカーソル |

### バリデーション

- `comedian_id` は1以上の整数であり、`standup_comedians` に存在し、`status = 'active'` であること。
- `after_id` と `before_id` は、指定された場合は1以上の整数であること。
- `after_id` と `before_id` は同時に指定できない。
- 不正なコメディアンIDまたはカーソル値の場合は `400 Bad Request` を返す。

### 取得順序・件数

- 投稿は `id DESC`（投稿IDの降順）で返す。
- 初回取得と過去投稿取得では最大10件を返す。
- `has_more` を判定するため、初回取得と過去投稿取得では最大11件を取得し、返却前に10件へ切り詰める。
- 新着取得（`after_id`）では、現行実装は該当する投稿をすべて返し、件数制限を設けない。

### 取得パターン

#### 初回取得

`after_id` と `before_id` のどちらも指定されていない場合。

- 対象コメディアンの投稿を新しい順に取得する。
- 最大10件を返す。
- 11件以上取得された場合は `has_more = true`、それ以外は `false`。

#### 新着投稿の取得

`after_id` が指定された場合。

- `id > after_id` の投稿を新しい順に取得する。
- 現行実装では、該当する投稿をすべて返す。
- `has_more` は `false` とする。
- クライアントは最後に確認した投稿IDを基準に新着投稿を取得する。

#### 過去投稿の追加取得

`before_id` が指定された場合。

- `id < before_id` の投稿を新しい順に取得する。
- `has_more` 判定のため最大11件を取得し、返却件数は最大10件とする。
- 11件目が存在した場合は `has_more = true`、それ以外は `false`。
- クライアントは表示中の最も古い投稿IDを `before_id` に指定する。

### GET 成功レスポンス

```json
{
  "success": true,
  "voices": [
    {
      "id": 123,
      "comedian_id": 45,
      "text": "投稿本文",
      "created_at": "2026-10-15 12:34:56"
    }
  ],
  "has_more": true
}
```

- `success`：処理成功を示す。
- `voices`：投稿データの配列。
- `id` と `comedian_id` は整数として返す。
- `created_at` はデータベースから取得した日時文字列を返す。
- `has_more`：初回取得または過去投稿取得で、さらに古い投稿があるかを示す。新着取得では現行実装上 `false`。

### GET エラー

| HTTPステータス | 意味 |
| --- | --- |
| `400` | コメディアンIDまたはカーソル値が不正、もしくはカーソルを同時指定した |
| `405` | 対応していないHTTPメソッド |
| `500` | サーバー内部エラー |

GET は公開情報の取得を想定し、ログイン必須とはしない。ただし、取得対象のコメディアンは有効状態である必要がある。

## 5. POST：投稿の登録

### 認証・権限チェック

投稿登録にはログインが必要。登録前に次を確認する。

1. `$_SESSION['services']['standup']['user_id']` にログインユーザーIDが存在する。
2. `users` テーブルに該当ユーザーが存在し、`status = 'active'` である。
3. ログインユーザーが有効なコメディアン権限を持ち、登録先のコメディアンIDを取得できる。

`comedian_id` はリクエスト本文から受け取らず、サーバー側でログインユーザーに紐づく有効なコメディアンIDを取得する。

### リクエスト本文

`Content-Type: application/json` を想定。

```json
{
  "text": "投稿本文"
}
```

### バリデーション

- リクエスト本文が有効な JSON で、配列としてデコードできること。
- `text` が文字列であること。
- `trim()` 後の本文が空文字列でないこと。
- `trim()` 後の本文が300文字以内であること。

### 登録処理

- `standup_comedian_voices` に `comedian_id` と `text` を登録する。
- `created_at` はデータベースのデフォルト値で自動設定する。

### POST 成功レスポンス

```json
{
  "success": true,
  "voice_id": 123
}
```

`voice_id` は登録された投稿IDを整数として返す。

### POST エラー

| HTTPステータス | 意味 |
| --- | --- |
| `400` | リクエスト本文または投稿本文が不正 |
| `401` | 未ログイン、またはユーザーが有効でない |
| `403` | 有効なコメディアン権限がない |
| `405` | 対応していないHTTPメソッド |
| `500` | サーバー内部エラー |

エラー時のレスポンス例：

```json
{
  "success": false,
  "error": "Text is required"
}
```

## 6. 共通エラー処理

- HTTPステータスコードを設定し、JSON形式でエラーを返す。
- 内部例外の詳細はクライアントに返さず、サーバーログに記録する。

## 7. クライアント側の取得方針

- 初回表示：`comedian_id` のみを指定する。
- 新着確認：最後に確認した投稿IDを `after_id` に指定する。
- 過去投稿の追加表示：表示中の最も古い投稿IDを `before_id` に指定する。
- 新着取得結果を画面に追加する際は投稿IDで既存投稿と照合し、重複を防ぐ。
- 取得結果は `id DESC` で返るため、画面上の表示順に合わせてクライアント側の配列操作を統一する。

## 8. 今後の検討事項

以下は現行実装で確定していない、または必要に応じて検討する事項。

- 新着取得（`after_id`）にも1回あたりの件数上限を設けるか。
- 投稿の編集・削除機能を追加するか。
- 投稿本文の文字数上限を定数などで一元管理するか。
- 投稿の並び順は投稿ID順を継続するか。
- POST に対する CSRF 対策など、追加のセキュリティ対策が必要か。
- コメディアンが非アクティブになった場合の既存投稿の扱い。

## 9. 現行仕様の要点

- 投稿はコメディアン単位で管理する。
- GET は公開取得、POST はログインおよび有効なコメディアン権限が必要。
- 初回取得と過去投稿取得は最大10件。
- 新着取得は `after_id` を使い、現行実装では該当投稿をすべて返す。
- 過去投稿取得は `before_id` を使い、`has_more` で追加取得の有無を示す。
- `after_id` と `before_id` は同時指定できない。
- 投稿IDを基準に、クライアント側で重複を防止する。
