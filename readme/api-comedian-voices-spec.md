# Standup API：コメディアンの一言 仕様

## 1. 概要

コメディアンが短いテキストを投稿し、コメディアンごとの一言一覧として取得できる機能。

一言の取得には一言IDを使ったカーソル方式を採用し、初回取得・新着取得・過去投稿の追加取得を区別する。

## 2. データベース

### テーブル：`standup_comedian_voices`

| カラム | 型 | 説明 |
| --- | --- | --- |
| `id` | `BIGINT UNSIGNED` | 一言ID。自動採番の主キー |
| `comedian_id` | `BIGINT UNSIGNED` | 一言投稿者のコメディアンID |
| `text` | `TEXT` | 一言本文 |
| `created_at` | `TIMESTAMP` | 一言投稿日時。登録時に自動設定 |

### 制約・インデックス

- `id` は主キーかつ自動採番。
- `comedian_id` は `standup_comedians.id` を参照する外部キー。
- コメディアンが削除された場合、関連する一言も `ON DELETE CASCADE` により削除される。
- `comedian_id` と `id` の複合インデックス `idx_standup_comedian_voices_comedian_id` を設定する。

## 3. API 共通仕様

- エンドポイント：`services/standup/voices.php`
- 対応メソッド：`GET`、`POST`
- `GET` は一言一覧の取得に使用する。
- `POST` は一言の登録・削除に使用する。
  - リクエスト本文に `voice_id` が指定されている場合は削除処理を行う。
  - `voice_id` が指定されていない場合は登録処理を行う。
- 対応外のメソッドでは `405 Method Not Allowed` を返し、`Allow: GET, POST` ヘッダーを設定する。
- レスポンス形式は JSON。
- `Content-Type: application/json; charset=UTF-8` を設定する。
- エラー時は原則として `{"success": false, "error": "..."}` を返す。
- 一言の登録・削除ではログイン認証と有効なコメディアン権限の確認を行う。
- 削除時のコメディアンIDはサーバー側で取得し、リクエスト本文の値を認可判定に使用しない。


## 4. GET：一言一覧の取得

### リクエストパラメーター

| パラメーター | 必須 | 説明 |
| --- | --- | --- |
| `comedian_id` | 必須 | 取得対象のコメディアンID |
| `after_id` | 任意 | 指定した一言IDより新しい一言を取得するカーソル |
| `before_id` | 任意 | 指定した一言IDより古い一言を取得するカーソル |

### バリデーション

- `comedian_id` は1以上の整数であり、`standup_comedians` に存在し、`status = 'active'` であること。
- `after_id` と `before_id` は、指定された場合は1以上の整数であること。
- `after_id` と `before_id` は同時に指定できない。
- 不正なコメディアンIDまたはカーソル値の場合は `400 Bad Request` を返す。

### 取得順序・件数

- 一言は `id DESC`（一言IDの降順）で返す。
- 初回取得と過去一言取得では最大20件を返す。
- `has_more` を判定するため、初回取得と過去一言取得では最大21件を取得し、返却前に20件へ切り詰める。
- 新着取得（`after_id`）では、現行実装は該当する一言をすべて返し、件数制限を設けない。

### 取得パターン

#### 初回取得

`after_id` と `before_id` のどちらも指定されていない場合。

- 対象コメディアンの一言を新しい順に取得する。
- 最大20件を返す。
- 21件目が存在する場合は `has_more = true`、それ以外は `false`。

#### 新着一言の取得

`after_id` が指定された場合。

- `id > after_id` の一言を新しい順に取得する。
- 現行実装では、該当する一言をすべて返す。
- `has_more` は `false` とする。
- クライアントは最後に確認した一言IDを基準に新着一言を取得する。

#### 過去一言の追加取得

`before_id` が指定された場合。

- `id < before_id` の一言を新しい順に取得する。
- `has_more` 判定のため最大21件を取得し、返却件数は最大20件とする。
- 21件目が存在した場合は `has_more = true`、それ以外は `false`。
- クライアントは表示中の最も古い一言IDを `before_id` に指定する。

### GET 成功レスポンス

```json
{
  "success": true,
  "voices": [
    {
      "id": 123,
      "comedian_id": 45,
      "text": "一言本文",
      "created_at": "2026-10-15 12:34:56"
    }
  ],
  "has_more": true
}
```

- `success`：処理成功を示す。
- `voices`：一言データの配列。
- `id` と `comedian_id` は整数として返す。
- `created_at` はデータベースから取得した日時文字列を返す。
- `has_more`：初回取得または過去一言取得で、さらに古い一言があるかを示す。新着取得では現行実装上 `false`。

### GET エラー

| HTTPステータス | 意味 |
| --- | --- |
| `400` | コメディアンIDまたはカーソル値が不正、もしくはカーソルを同時指定した |
| `405` | 対応していないHTTPメソッド |
| `500` | サーバー内部エラー |

GET は公開情報の取得を想定し、ログイン必須とはしない。ただし、取得対象のコメディアンは有効状態である必要がある。

## 5. POST：一言の登録・削除

### 5.1 認証・権限チェック

一言の登録・削除にはログインが必要。処理前に次を確認する。

1. `$_SESSION['services']['standup']['user_id]` にログインユーザーIDが存在する。
2. `users` テーブルに該当ユーザーが存在し、`status = 'active'` である。
3. ログインユーザーが有効なコメディアン権限を持ち、操作対象となるコメディアンIDを取得できる。

`comedian_id` はリクエスト本文から受け取らず、サーバー側でログインユーザーに紐づく有効なコメディアンIDを取得する。

### 5.2 リクエストの判定

リクエスト本文は `Content-Type: application/json` を想定する。

処理内容はリクエスト本文によって判定する。

- `voice_id` が指定されている場合：一言の削除
- `voice_id` が指定されていない場合：一言の登録

### 5.3 一言の登録

#### リクエスト本文

```json
{
  "text": "一言本文"
}
```

#### バリデーション

- リクエスト本文が有効なJSONで、オブジェクトとしてデコードできること。
- `text` が文字列であること。
- `trim()` 後の本文が空文字列でないこと。
- `trim()` 後の本文が300文字以内であること。

#### 登録処理

- `standup_comedian_voices` に `comedian_id` と `text` を登録する。
- `created_at` はデータベースのデフォルト値で自動設定する。

#### 成功レスポンス

```json
{
  "success": true,
  "voice_id": 123,
  "comedian_id": 45,
  "created_at": "2026-10-15 12:34:56"
}
```

`voice_id` は登録された一言IDを整数として返す。

### 5.4 一言の削除

#### リクエスト本文

```json
{
  "voice_id": 123
}
```

#### バリデーション

- リクエスト本文が有効なJSONで、オブジェクトとしてデコードできること。
- `voice_id` が1以上の整数であること。
- `voice_id` と `text` が同時に指定された場合は、リクエスト不正として `400 Bad Request` を返す。

#### 削除処理

- 削除対象の `voice_id` と、サーバー側で取得したログインユーザーのコメディアンIDを使用して削除対象を特定する。
- 削除対象は `standup_comedian_voices` テーブルの `id` と `comedian_id` の両方が一致する一言に限定する。
- リクエスト本文から `comedian_id` を受け取らず、ログインユーザー自身の一言のみ削除できるようにする。
- 削除対象が存在しない場合、またはログインユーザーのコメディアンに紐づかない場合は、削除失敗として扱う。
- 削除件数が1件であることを確認する。

#### 成功レスポンス

```json
{
  "success": true,
  "voice_id": 123
}
```

`voice_id` は削除した一言IDを整数として返す。

#### 削除エラー

| HTTPステータス | 意味 |
| --- | --- |
| `400` | リクエスト本文または `voice_id` が不正 |
| `401` | 未ログイン、またはユーザーが有効でない |
| `403` | 有効なコメディアン権限がない |
| `404` | 削除対象の一言が存在しない、または削除できない |
| `405` | 対応していないHTTPメソッド |
| `500` | サーバー内部エラー |

### 5.5 POST 共通事項

- 登録・削除のいずれも、ログイン状態と有効なコメディアン権限を確認する。
- エラー時は `{"success": false, "error": "..."}` 形式のJSONを返す。
- 内部例外の詳細はクライアントに返さず、サーバーログに記録する。


## 6. 共通エラー処理

- HTTPステータスコードを設定し、JSON形式でエラーを返す。
- 内部例外の詳細はクライアントに返さず、サーバーログに記録する。

## 7. クライアント側の取得方針

- 初回表示：`comedian_id` のみを指定する。
- 新着確認：最後に確認した一言IDを `after_id` に指定する。
- 過去一言の追加表示：表示中の最も古い一言IDを `before_id` に指定する。
- 新着取得結果を画面に追加する際は一言IDで既存一言と照合し、重複を防ぐ。
- 取得結果は `id DESC` で返るため、画面上の表示順に合わせてクライアント側の配列操作を統一する。

## 9. 現行仕様の要点

- 一言はコメディアン単位で管理する。
- `GET` は公開情報の取得を想定し、ログイン認証を必須としない。ただし、取得対象のコメディアンは有効状態である必要がある。
- `POST` は一言の登録・削除に使用し、ログインおよび有効なコメディアン権限が必要。
- 一言の登録時は、本文が空でなく、300文字以内であることを確認する。
- 一言の削除時は `voice_id` を指定する。
- 削除対象は、ログインユーザーに紐づくコメディアンの一言に限定する。
- 削除対象が存在しない場合、またはログインユーザーのコメディアンに紐づかない場合は、削除失敗として扱い、`404` を返す。
- 初回取得と過去一言取得は最大20件。
- 新着取得は `after_id` を使い、現行実装では該当する一言をすべて返す。
- 過去一言取得は `before_id` を使い、`has_more` で追加取得の有無を示す。
- `after_id` と `before_id` は同時指定できない。
- 一言IDを基準に、クライアント側で重複を防止する。
- 一言の削除成功後は、クライアント側のキャッシュと画面表示から該当する一言を削除する。
