# Standup API：会場の登録・編集 仕様

## 1. 概要

Standup Spotにおける会場の新規登録および既存会場の編集を行う。

- **API:** `services/standup/venue.php`
- **HTTPメソッド:** `POST`
- **データベース:** `standup_venues`、`standup_venue_managers`
- **レスポンス形式:** JSON

会場の初期データは `/init?service=standup` から取得する。

会場の登録・編集APIは、ログイン状態、ユーザーの有効なロール、会場の管理者設定に基づいて処理を行う。

## 2. データベース

### 2.1 `standup_venues`

会場情報を管理するテーブル。

| カラム | 型 | 説明 |
|---|---|---|
| `id` | BIGINT UNSIGNED | 主キー、自動採番 |
| `name` | VARCHAR(255) | 会場名、必須 |
| `address` | VARCHAR(500) | 住所 |
| `latitude` | DECIMAL(10,7) | 緯度、NULL許可 |
| `longitude` | DECIMAL(10,7) | 経度、NULL許可 |
| `stations` | JSON | 最寄り駅情報の配列、デフォルトは空配列 |
| `instagram` | VARCHAR(255) | Instagram |
| `tiktok` | VARCHAR(255) | TikTok |
| `youtube` | VARCHAR(255) | YouTube |
| `x` | VARCHAR(255) | X |
| `message` | TEXT | 会場からのメッセージ |
| `message_for_comedian` | TEXT | コメディアン向けメッセージ |
| `status` | VARCHAR(20) | 状態、デフォルトは `active` |
| `created_at` | TIMESTAMP | 作成日時 |
| `updated_at` | TIMESTAMP | 更新日時 |

`id` は新規登録時に自動採番する。`created_at` と `updated_at` はDB側で管理する。

### 2.2 `standup_venue_managers`

会場と管理者ユーザーの紐付けを管理するテーブル。

| カラム | 型 | 説明 |
|---|---|---|
| `id` | BIGINT UNSIGNED | 主キー、自動採番 |
| `venue_id` | BIGINT UNSIGNED | 会場ID |
| `user_id` | BIGINT UNSIGNED | ユーザーID |
| `status` | VARCHAR(20) | 管理者割り当ての状態 |
| `created_at` | TIMESTAMP | 作成日時 |
| `updated_at` | TIMESTAMP | 更新日時 |

`(venue_id, user_id)` に UNIQUE 制約を設定し、同じユーザーを同じ会場に重複登録できないようにする。

会場またはユーザーが物理削除された場合、外部キーの `ON DELETE CASCADE` により対応する管理者レコードも削除する。

管理者としての権限は、`status = 'active'` のレコードによって判定する。

## 3. API共通仕様

### 3.1 リクエスト

- HTTPメソッドは `POST` のみ。
- リクエストデータは `$_POST` から取得する。
- `stations` はJSON文字列として送信する。
- `id` が未指定または空文字の場合は新規登録とする。
- `id` が指定されている場合は既存会場の更新とする。

### 3.2 認証・利用条件

次の条件を満たす必要がある。

1. ログインしていること。
2. `users.status = 'active'` であること。
3. Standupの有効なコメディアン、または有効な会場管理者ロールを持っていること。

有効なコメディアンとは、Standupの有効な `comedian` ロールを持ち、かつ有効なコメディアンレコードが存在するユーザーを指す。

## 4. POSTパラメータ

| パラメータ | 必須 | 説明 |
|---|---|---|
| `id` | 新規登録では不要 | 会場ID。未指定・空文字なら新規登録 |
| `name` | 必須 | 会場名 |
| `address` | 権限に応じて保存 | 住所 |
| `latitude` | 任意 | 緯度 |
| `longitude` | 任意 | 経度 |
| `stations` | 任意 | 最寄り駅情報のJSON文字列 |
| `instagram` | 任意 | Instagram |
| `tiktok` | 任意 | TikTok |
| `youtube` | 任意 | YouTube |
| `x` | 任意 | X |
| `message` | 権限に応じて保存 | 会場からのメッセージ |
| `message_for_comedian` | 権限に応じて保存 | コメディアン向けメッセージ |

### 4.1 入力値の検証

- `name` は必須。前後の空白を除去し、空文字はエラーとする。
- `name` は最大255文字。
- `id` が指定されている場合は、正の整数を表す文字列であること。
- `latitude` と `longitude` は数値として検証し、許容範囲を超える値はエラーとする。
- 緯度・経度の空文字は `NULL` として扱う。
- `stations` はJSONデコード後に配列であることを検証する。
- 文字列項目は各カラムの型・長さに合わせて検証する。

`stations` はDBではJSON型として保存し、レスポンスでは配列として返す。

リクエストに含まれない項目は、原則として更新しない。編集権限のない項目は保存対象から除外し、エラーにはしない。

## 5. 権限仕様

### 5.1 新規登録

新規登録は、有効な会場管理者ロールを持つユーザーが実行できる。

新規登録したユーザーは、作成した会場の管理者として `standup_venue_managers` に登録される。

有効なコメディアンロールのみを持つユーザーは、新規登録できない。

### 5.2 既存会場の編集

編集対象の会場は `status = 'active'` であること。

編集権限は、その会場に有効な管理者が存在するかどうかによって判定する。

| 会場の状態 | 編集可能なユーザー |
|---|---|
| 有効な管理者が1人以上いる | 有効な会場管理者ロールを持ち、かつ対象会場の有効な管理者として登録されているユーザー |
| 有効な管理者がいない | 有効なコメディアン、または有効な会場管理者ロールを持つユーザー |

会場管理者ロールを持つだけで対象会場の管理者に割り当てられていないユーザーは、有効な管理者がいる会場を編集できない。

有効な管理者がいない会場では、会場管理者ロールを持つユーザーも編集できる。ただし、そのユーザーが対象会場の管理者として登録されていない場合は、コメディアン向けの編集項目のみ保存できる。

### 5.3 編集可能な項目

| 項目 | 有効なコメディアン | 対象会場の有効な管理者 | 未割り当ての会場管理者 |
|---|---|---|---|
| `name` | 保存可 | 保存可 | 保存可 |
| `latitude` / `longitude` | 保存可 | 保存可 | 保存可 |
| `stations` | 保存可 | 保存可 | 保存可 |
| `instagram` / `tiktok` / `youtube` / `x` | 保存可 | 保存可 | 保存可 |
| `address` | 保存不可 | 保存可 | 保存不可 |
| `message` | 保存不可 | 保存可 | 保存不可 |
| `message_for_comedian` | 保存不可 | 保存可 | 保存不可 |

有効な管理者がいない会場をコメディアンが編集する場合も、会場管理者専用項目は保存しない。

編集権限のない項目がPOSTに含まれていても、その項目を無視して、権限のある項目のみを保存する。

## 6. 登録・更新処理

### 6.1 新規登録

1. HTTPメソッド、ログイン状態、ユーザーの状態、ロールを検証する。
2. `name` などの入力値を検証する。
3. 会場情報を `standup_venues` に登録する。
4. 登録者を `standup_venue_managers` に有効な管理者として登録する。
5. トランザクションをコミットする。
6. 登録した会場情報を取得し、成功レスポンスを返す。

会場情報の登録と管理者登録は、同一トランザクション内で処理する。

### 6.2 更新

1. HTTPメソッド、ログイン状態、ユーザーの状態、ロールを検証する。
2. `id` と入力値を検証する。
3. 更新対象の会場が存在し、有効状態であることを確認する。
4. 対象会場の有効な管理者の有無を確認する。
5. 権限に応じて編集可否と保存可能な項目を判定する。
6. 許可された項目のみ更新する。
7. トランザクションをコミットする。
8. 更新後の会場情報を取得し、成功レスポンスを返す。

更新対象の会場が存在しない場合や、無効状態の場合はエラーとする。

## 7. 成功レスポンス

新規登録・更新ともに、次の形式で返す。

```json
{
  "success": true,
  "id": 123,
  "venue": {
    "id": "123",
    "name": "サンプル会場",
    "address": "",
    "latlng": {
      "lat": null,
      "lng": null
    },
    "stations": [],
    "socialmedia": {
      "instagram": "",
      "tiktok": "",
      "youtube": "",
      "x": ""
    },
    "message": "",
    "message_for_comedian": "",
    "status": "active"
  }
}
```

### 7.1 レスポンス項目

- `success`: 成功時は `true`。
- `id`: 登録・更新対象の会場ID。数値。
- `venue`: 登録・更新後の会場情報。

`venue.id` は文字列として返す。

`venue.latlng.lat` と `venue.latlng.lng` は数値または `null`。緯度・経度が未設定の場合は `null` とする。

`venue.stations` は配列として返す。

`venue.socialmedia` にSNS情報をまとめて返す。

成功レスポンスの `venue` は、登録・更新後の会場レコードを取得して生成する。取得に失敗した場合は、`venue: null` の成功レスポンスを返すのではなく、エラーとして扱う。

## 8. エラーレスポンス

エラー時は次の形式で返す。

```json
{
  "success": false,
  "error": "エラーメッセージ"
}
```

| HTTPステータス | 主な発生条件 |
|---|---|
| `400 Bad Request` | 入力値不正、ID不正、必須項目不足 |
| `401 Unauthorized` | 未ログイン、ユーザーが無効 |
| `403 Forbidden` | ロール不足、会場の編集権限不足 |
| `404 Not Found` | 対象会場が存在しない |
| `405 Method Not Allowed` | POST以外のリクエスト |
| `500 Internal Server Error` | DBエラーなどの予期しない内部エラー |

エラー時は `success: false` とし、成功時の `id` および `venue` は返さない。

## 9. 補足事項

- 会場の削除は本APIでは扱わず、別API `venue_delete.php` で処理する。
- 会場の物理削除時は、外部キー制約により管理者レコードも削除される。
- 有効な管理者の判定には `standup_venue_managers.status = 'active'` を使用する。
- 管理者がいない会場で未割り当ての会場管理者が編集した場合、会場管理者専用項目は保存しない。
- 本仕様書は、APIの実装およびDB定義に合わせて管理する。
