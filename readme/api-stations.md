# Stations API 仕様書

## 1. 概要

指定された緯度・経度を中心に、指定半径内にある駅を取得する。

各駅について、駅名、中心地点からの距離、乗り入れ路線名を返す。

- エンドポイント：`/stations`
- HTTPメソッド：`GET`
- レスポンス形式：JSON
- 認証：不要
- アクセス制限：許可されたリファラーのみ

## 2. リクエスト

### 2.1 URL

```text
GET /stations?lat={緯度}&lng={経度}&distance={距離}
```

### 2.2 パラメータ

| パラメータ | 型 | 必須 | 説明 |
|---|---|---|---|
| `lat` | number | 必須 | 検索中心地点の緯度 |
| `lng` | number | 必須 | 検索中心地点の経度 |
| `distance` | number | 必須 | 検索半径（メートル） |

### 2.3 パラメータの制約

| パラメータ | 条件 |
|---|---|
| `lat` | -90以上、90以下 |
| `lng` | -180以上、180以下 |
| `distance` | 0より大きく、20,000,000以下 |

数値以外の値、有限数でない値、または許容範囲外の値が指定された場合はエラーを返す。

### 2.4 リクエスト例

```text
/stations?lat=35.6812&lng=139.7671&distance=1000
```

## 3. アクセス制限

`app/config/domains.php` で定義された `$allowedOrigins` を使用し、リクエストの `HTTP_REFERER` から取得したオリジンを照合する。

- 許可されたオリジンからのリクエストのみ受け付ける。
- リファラーが存在しない場合は拒否する。
- 許可されていないオリジンの場合は HTTP 403 を返す。

なお、リファラーは偽装可能なため、この制限は補助的なアクセス制御であり、強固な認証の代替ではない。

## 4. 駅情報の取得・集約

### 4.1 検索対象

駅データベースの `m_station` および `m_line` を使用する。

検索中心地点から指定半径内に位置する駅を対象とする。

検索時は緯度・経度による矩形範囲で候補を絞り込み、`ST_Distance_Sphere()` によって中心地点からの距離を算出する。

### 4.2 駅のグループ化

駅のグループ化には `m_station.station_g_cd` を使用する。

- `station_g_cd > 0` の駅を対象とする。
- 同一の `station_g_cd` を持つ駅は同一グループとして扱う。
- 同一グループ内では、中心地点から最も近い駅データを代表として使用する。
- 代表駅の駅名と距離を採用する。
- 代表駅が検索半径内にある場合、そのグループをレスポンスに含める。

駅名が同じでも `station_g_cd` が異なる場合は、別の駅として扱う。

### 4.3 路線名の集約

代表駅が属するグループについて、同一の `station_g_cd` を持つ駅データから路線名を取得する。

- 同じ路線名が複数回存在する場合は重複を除去する。
- 路線名は `lines` 配列に格納する。
- 路線名は文字列として返す。

### 4.4 距離の計算

中心地点から代表駅までの距離をメートル単位で算出し、整数に丸めて返す。

### 4.5 並び順

中心地点からの距離が近い順に返す。

距離が同じ場合は、駅グループコードの昇順とする。

## 5. 正常レスポンス

### 5.1 レスポンス形式

正常時は駅情報の配列を直接返す。

| フィールド | 型 | 説明 |
|---|---|---|
| `name` | string | 駅名 |
| `distance` | integer | 中心地点からの距離（メートル） |
| `lines` | array of string | 乗り入れ路線名の配列 |

`station_g_cd`、緯度、経度はレスポンスに含めない。

### 5.2 レスポンス例

```json
[
  {
    "name": "東京",
    "distance": 120,
    "lines": [
      "JR山手線",
      "JR中央線"
    ]
  },
  {
    "name": "有楽町",
    "distance": 822,
    "lines": [
      "JR山手線",
      "JR京浜東北線"
    ]
  }
]
```

### 5.3 該当する駅がない場合

該当する駅がない場合は、空配列を返す。

```json
[]
```

## 6. エラーレスポンス

エラー時は以下の形式で返す。

```json
{
  "success": false,
  "error": "エラーメッセージ"
}
```

### 6.1 HTTPステータス

| HTTPステータス | 発生条件 | メッセージ例 |
|---|---|---|
| `400 Bad Request` | 必須パラメータの欠落、数値以外の指定、範囲外の値 | `パラメータが不正です: lat` |
| `403 Forbidden` | リファラーが未指定、または許可されていない | `アクセスが許可されていません。` |
| `405 Method Not Allowed` | GET以外のHTTPメソッド | `許可されていないリクエストです。` |
| `500 Internal Server Error` | データベース接続エラー、SQLエラーなど | `サーバー内部でエラーが発生しました。` |

内部エラーの詳細はサーバーログに記録し、クライアントには詳細を返さない。

## 7. データソース

駅データベースの以下のテーブルを使用する。

| テーブル | 用途 |
|---|---|
| `m_station` | 駅名、駅グループコード、緯度・経度、路線コード |
| `m_line` | 路線名 |

## 8. 備考

- 距離の単位はメートル。
- 駅グループコードは内部的な集約にのみ使用し、レスポンスには含めない。
- リファラー制限はブラウザからの利用を想定した補助的な制限であり、リクエスト元の真正性を保証するものではない。
